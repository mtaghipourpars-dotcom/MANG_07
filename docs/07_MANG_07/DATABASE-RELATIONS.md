# پایگاه داده و روابط تعاملی MANG_07

مبنای این مرحله نسخهٔ صحه‌گذاری‌شدهٔ `d669570ee3865466312fc79997b7501389eca548` است. این مرحله دو تغییر مصوب دارد: ذخیره‌سازی سمت سرور و امکان بررسی زندهٔ اثر تغییر ورودی‌های عملیاتی. ظاهر و مسیرهای صفحهٔ اصلی بر پایهٔ نسخهٔ مبنا باقی می‌مانند.

## اجرا و ذخیره‌سازی

برای اجرای دمو، Node.js نسخهٔ ۲۲٫۱۳ به بالا لازم است. از ریشهٔ مخزن اجرا کنید.

```sh
npm install
npm start
```

دمو در `http://localhost:3000/` در دسترس است. مسیر پیش‌فرض SQLite، فایل `.pvpt/demo.sqlite` است. متغیر `PVPT_DATABASE_PATH` مسیر دیگری را مشخص می‌کند. در محیط میزبان، مسیر را روی فضای پایدار قرار دهید تا با تعویض نمونهٔ اجرا باقی بماند. فایل بانک خارج از مسیرهای استاتیک ارائه می‌شود. `/api/health` دسترسی به SQLite را بررسی می‌کند.

| داده | محل و شیوهٔ ذخیره |
|---|---|
| مرجع محصول، پروژه، سفارش، عملیات، منبع، تعهد و دادهٔ نمونه | فایل‌های مبنای مخزن هنگام راه‌اندازی به SQLite وارد می‌شوند. برنامه نسخهٔ مرجع را از API می‌خواند. |
| چالش، نسخه‌های اثر، گزینه، مصوبه، اجرا، نتیجه و درس‌آموخته | در فضای کاری دمو در SQLite، با شناسهٔ پرونده و پیوندهای اعتبارسنجی‌شده |
| سوابق قبلی دمو، ثبت‌های کاربردی، سناریوهای ثبت‌شده و تنظیمات زبان و پوسته | در بخش جداگانهٔ همان فضای کاری در SQLite |
| ورودی پیش‌نمایش ثبت‌نشده و فیلترهای ناوبری | موقت در صفحه. دکمهٔ ثبت سناریو برای نگهداشت پیش‌نمایش قابل محاسبه در پایگاه داده است. |

فضای کاری دمو با کوکی اختصاصی مرورگر شناخته می‌شود. همان شناسه بعد از بارگذاری مجدد و راه‌اندازی دوباره به همان داده‌ها وصل می‌شود. فضای مرورگر ناشناس جدید مستقل است. دادهٔ قدیمی مرورگر فقط برای بخش خالی بانک و پس از تأیید ذخیره منتقل می‌شود. درخواست هم‌زمان بر مبنای نسخهٔ قدیمی با تعارض بازمی‌گردد. برنامه نسخهٔ تازه را بارگذاری می‌کند و پیام ثبت موفق تنها پس از پاسخ سرور ظاهر می‌شود. نسخهٔ مصوب و سوابق ثبت‌شده در مسیر عادی گردش کار بازنویسی نمی‌شوند.

## روابط و فرمول‌ها

پنل بررسی روابط در سه مسیر «پروژه‌ها ← زنجیره تعهد»، «نقشهٔ ریسک و ارزش ← زنجیره اثر» و «منابع و ظرفیت ← ظرفیت و بارگذاری» در دسترس است. روی اشیای پیوندخورده می‌توان حرکت کرد و از پرونده به فرم اثر، راهکار یا سابقهٔ تصمیم رسید.

| ورودی تغییرپذیر | خروجی قابل مشاهده |
|---|---|
| پروژه، سفارش، فعالیت، منبع و پروندهٔ انتخاب‌شده | زنجیرهٔ وابستگی و اشیای مرتبط از شناسه‌های ثبت‌شده |
| تقاضای فعالیت و ظرفیت قابل تخصیص | مجموع تقاضای فعالیت‌های مرتبط و کسری `max(0, demand − capacity)`. فرض پنجرهٔ مشترک صریح است. |
| خط مبنا، پیش‌بینی بدون اقدام و پیش‌بینی با گزینه | اثر چالش = بدون اقدام − مبنا. زمان بازیافته = بدون اقدام − با گزینه. اثر باقی‌مانده = با گزینه − مبنا. مقایسه برای هر تعهد و واحد جداست. |
| موعد سخت و سقف بودجه | پیش‌بینی پس از موعد یا هزینهٔ بالاتر از سقف، گزینه را مسدود می‌کند. بازهٔ نامطمئن، وضعیت بررسی می‌گیرد. |
| مبلغ وصول، نرخ، روز بازیافته، هزینهٔ تکمیل و هزینهٔ اقدام | منفعت زمانی = مبلغ × نرخ سالانه × روز بازیافته ÷ ۳۶۵. خالص برآوردی، منفعت زمانی و تغییر هزینهٔ تکمیل را پس از یک بار کسر هزینهٔ اقدام نشان می‌دهد. |
| مدت توقف یا دادهٔ فاقد رابطهٔ قابل محاسبه | تعهدهای وابسته برای بازبینی علامت می‌خورند. تاریخ و مبلغ تازه پس از ورود برآورد یا دادهٔ معتبر محاسبه می‌شود. |

نتیجهٔ پیش‌نمایش و نسخهٔ مصوب جدا نمایش داده می‌شوند. اگر سناریو ذخیره شود، ورودی‌ها، شناسه‌های مرتبط و خروجی محاسبه با عنوان آموزشی در «شواهد و یکپارچگی» باقی می‌مانند. ذخیرهٔ سناریو خط مبنای داده و نسخهٔ تصمیم را تغییر نمی‌دهد.

این اجرا دموی پایدار تک‌میزبان است. احراز هویت و اختیارات سازمانی، اتصال SAP و PostgreSQL چندنمونه‌ای جزو معماری استقرار عملیاتی‌اند.
