# بازاجرای سناریوهای PVPT از بانک خالی

این بسته برای دموی آموزشی MANG_07 است. شناسه‌های پایه از دو فایل نسخه‌دار در `data/` خوانده می‌شوند. وضعیت‌ها، آثار روزشمار و رکوردهای اجرا داده عملیاتی SAP نیستند. در این بازاجرا از مقدار تصادفی استفاده نمی‌شود. شناسه هر سناریو از ترتیب ثابت ورودی‌ها به دست می‌آید.

## بازتولید

```powershell
python scenario-lab/reexecute.py --output .pvpt/audit-new --workers 12
```

پوشه خروجی باید تازه باشد. Node.js 22.13 یا جدیدتر، npm و Python 3.10 یا جدیدتر برای **بازسازی** لازم‌اند. برنامه یک بانک سناریوی تازه و یک فضای کار آزمون جداگانه می‌سازد. سپس برنامه واقعی را روی loopback اجرا و درخواست‌های HTTP را در چند دسته پردازش می‌کند. `execution.jsonl` شواهد خام و `report.json` شاخص‌ها، اثر انگشت ورودی و نتیجه کنترل را نگه می‌دارند. ثبت SQLite پس از مرحله HTTP به صورت یک تراکنش انجام می‌شود. قطع اجرای HTTP بانک ناقصِ «تأییدشده» منتشر نمی‌کند.

## مدل وضعیت

| محور | دامنه پوشش |
|---|---|
| کاتالوگ | ۷۵ مرجع × ۸ مرحله × ۳ گزینه × ۱۲ وضعیت ورودی × ۲ حالت هم‌پوشانی |
| مانع تصمیم | FEASIBLE، BLOCKED_DONOR، BLOCKED_RESERVATION، EXPIRED، STALE، WAIT_EVIDENCE |
| تصمیم مدل | APPROVED، NOT_APPROVED، NOT_REQUIRED، NO_ACTION |
| اجرای مدل | NOT_STARTED، COMPLETED، FAILED، IN_PROGRESS، PARTIAL، CANCELLED، SUPERSEDED |
| مشاهده مدل | NOT_APPLICABLE، PENDING، PARTIALLY_VERIFIED، VERIFIED |
| پرونده برنامه | DRAFT، REPORTED، SCOPED، ASSESSED، APPROVED، DECLINED، EXECUTED، OBSERVED، CLOSED |
| حدود | وضعیت‌های تعریف شده و گذارهای قابل دستیابی این مدل. داده‌های تأیید SAP، نقش واقعی شرکت و ترکیب نامحدود ورودی‌های کاربر خارج از شواهد این دمو هستند. |

«FAILED» در مدل می‌تواند نتیجه درست یک سناریوی آموزشی باشد. PASS و FAIL اجرای آزمون از نتیجه مدل مستقل‌اند. مدل مرجع مستقل `audit_oracle.py` همه ترکیب‌ها، آثار و رویدادها را با بانک تازه تطبیق می‌دهد. آزمون HTTP تغییرات پرونده و بازیابی نسخه نهایی را از برنامه می‌خواند.

## قرارداد ذخیره‌سازی

- `educational_audit_run` شناسه بازاجرا، اثر نسخه، شمار مورد انتظار و digest محتوایی.
- `educational_audit_test` نتیجه، پیوند به سناریو، دلیل تصمیم، درس و JSON شواهد برای هر آزمون.
- `educational_audit_event` رویدادهای مرتب شده با کلید مشترک اجرا و آزمون.
- `scenario`، `effect` و `event` کاتالوگ و آثار مدل. نقش‌های برنامه از فضای کار آزمون استفاده می‌کنند.
- متن درس‌آموخته به مشاهده همین سناریو محدود است. در نبود شاهدِ نتیجه، دلیل فقدان مشاهده ثبت می‌شود. تصمیم‌های سازمانی یا درس واقعی از داده آموزشی استنتاج نشده است.

```sql
SELECT t.test_id, t.outcome, t.decision, t.lesson
FROM educational_audit_test t
JOIN scenario s ON s.id = t.scenario_id AND s.stage = t.stage
WHERE s.id = 'S000013';
```

## تحویل و نسبت آن با Google AI Studio

کد برنامه با Node و SQLite محلی اجرا می‌شود. ماشین برای بازاجرا باید فرمان و ورودی‌های همین بسته را مصرف کند. بانک آزمون موجود برای نمایش و پاسخ API کافی است. برای اجرای میزبانی‌شده در Google AI Studio، راهنمای `DEV/local/ai-studio.md` و شواهد واقعی همان محیط ملاک پذیرش‌اند. بازاجرای فعلی در فضای کار محلی انجام شده است.
