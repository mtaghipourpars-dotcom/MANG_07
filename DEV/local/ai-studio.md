# اجرای همین نسخه در Google AI Studio

در Build mode از منوی افزودن فایل، Import from GitHub را انتخاب کنید. مخزن MANG_07 را باز کنید و مطابقت فایل‌های واردشده با نسخه تحویلی را کنترل کنید. بخش Code برای بازبینی تغییرات و بخش GitHub در Settings برای همگام‌سازی در دسترس است. فایل ZIP نیز برای اجرای محلی قابل دریافت است. Google برای وب از محیط سمت سرور Node و بسته‌های npm پشتیبانی می‌کند. [مستندات رسمی Google](https://aistudio.google.com/docs/aistudio-build-mode)

## متن ورودی عامل

نسخه ورودی را با شناسه کامیت تحویل و فایل‌های `DEV/local/contracts.json`، `DEV/api-contract.json`، `DEV/technical-spec.json` و `DEV/local/architecture.md` تطبیق بده. اگر محیط شناسه Git را نشان نمی‌دهد، برابری فایل‌های قرارداد را با نسخه مبنا بررسی و شیوه بررسی را ثبت کن.

۱. قابلیت اجرای Node 22.13 یا بالاتر و Python 3.10 یا بالاتر و دسترسی فایل SQLite را بررسی کن. نسخه‌ها و مسیرهای معتبر را در گزارش بنویس. دو متغیر پیکربندی `PVPT_DATABASE_PATH=.pvpt/demo.sqlite` و `PVPT_TOTAL_DEMO_DB=.pvpt/total-demo.sqlite` هستند. بانک سناریو را از کد و شواهد بازتولیدشده مخزن بخوان. اگر Python در Build در دسترس نیست، بانک بازتولید و تأییدشده با `scenario-lab/build_bank.py` را از میزبان معتبر به مسیری قابل خواندن منتقل کن. اگر فایل یا مسیر پایدار در دسترس نیست، قابلیت همان میزبان را BLOCKED ثبت کن. مستندات Build تضمینی برای نصب Python یا ماندگاری فایل SQLite محلی این برنامه ارائه نمی‌کنند.

۲. اجرای روی رایانه کاربر با `npm run localhost` انجام می‌شود. برای پیش‌نمایش میزبانی‌شده از تنظیم پورت و نشانی شنود همان میزبان استفاده کن؛ نشانی حلقه محلی پیش‌فرض ابزار localhost برای رایانه کاربر است. نتیجه درخواست به `/api/health` و `/api/total-demo/summary` را از سرور همان نسخه ثبت کن. درستی مسیرها و شمار ۴۳٬۲۰۰ رکورد آموزشی را در پاسخ بررسی کن.

۳. گیت‌ها را طبق `contracts.json` اجرا کن. با شکست هر مرحله، کد مؤلفه مسئول و مدارک آن را بازبینی کن، سپس آزمون‌های مرحله و وابستگان آن را تکرار کن. شاهد اجرای محلی، CI، پیش‌نمایش AI Studio و پذیرش انسانی هر کدام در محیط خود ثبت شوند. طراحی محصول، مسیر اصلی، زبان‌ها و دو پوسته را مطابق قرارداد قابل اجرا نگه دار. برای داده مفقود، علت و منبع موردنیاز را ثبت کن.

۴. خروجی ماشین باید شامل تغییرات واقعی، شناسه نسخه، فرمان هر آزمون، نتیجه واقعی و مسیر شواهد باشد. انتشار در میزبان عمومی یک عمل مستقل است. راهنمای رسمی پیش‌نمایش و گزینه‌های میزبانی در [مستندات Build](https://aistudio.google.com/docs/aistudio-build-mode) آمده است.
